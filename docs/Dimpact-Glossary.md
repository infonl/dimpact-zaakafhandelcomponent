# Dimpact Glossary

This glossary promotes a [Ubiquitous Language](https://martinfowler.com/bliki/UbiquitousLanguage.html),
so that the team can communicate with the business more effectively.
It lists the terms of the business domain with their agreed-upon meaning.

The source of this list is the
[Glossary page in the Dimpact Confluence](https://dimpact.atlassian.net/wiki/spaces/PZW/pages/4522123/Glossary).
Also see the overall PodiumD Glossary in the same Confluence, which partly overlaps with this list.

## Language

As stated in [CONTRIBUTING.md](../CONTRIBUTING.md#language):

> Please use English for all communication, contributions and reported issues.
> The preferred language for Dutch domain-specific terminology (typically within the context of 'zaakgericht werken'),
> however, is Dutch.

The terms in this glossary are Dutch domain-specific terminology. Therefore:

- Use the Dutch term in code: in class, function, variable, database and REST API names, and in documentation.
  Write `zaak`, `zaaktype`, `behandelaar` and `signalering`, not `case`, `caseType`, `caseManager` and `notification`.
- Do not translate these terms into English, not even partly. Combine them with English words where needed,
  for example `ZaakService`, `RestZaak` or `findZaaktypeByUuid`.
- Write everything else, such as comments, commit messages, pull requests and the rest of the documentation, in English.

The English meaning in the table below explains a term. It is not a name to use in code.
