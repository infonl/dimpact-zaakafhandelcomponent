# Use Trivy for Docker image scanning and Snyk for dependency scanning

## Context and Problem Statement

ZAC must be a secure component. The ZAC Docker image and the libraries ZAC depends on may contain security
vulnerabilities. Which tools do we use to scan them, and when?

## Decision Drivers

* Detect vulnerabilities in the published Docker image soon after they become known
* Free to use
* Scan results that we act on, in the GitHub Security tab
* No scans that slow down every pull request without adding value

## Considered Options

* Snyk
* Trivy
* Grype
* CoGuard

## Decision Outcome

Chosen option: "Trivy" for the Docker image and "Snyk" (free community account) for the dependencies:

* Trivy scans the published `latest` ZAC Docker image every weekday, for critical and high vulnerabilities.
* Trivy scans the `Dockerfile` and the Helm charts for misconfigurations in every pull request that changes them.
* Snyk scans the Node and Gradle dependencies every week.
* All results are uploaded to the GitHub Security tab.

### Consequences

* Good, because new vulnerabilities in the published Docker image are found within a working day.
* Good, because pull requests are not slowed down by a Docker image scan.
* Bad, because a vulnerability in the Docker image is found after the pull request that introduced it is merged.

### Confirmation

The workflows `.github/workflows/trivy-docker-image-scan.yml`, `.github/workflows/trivy-iac-scan.yml` and
`.github/workflows/snyk-code-scan.yml`.

## Pros and Cons of the Options

### Snyk

* Good, because it takes a developer-first approach: it guides developers in fixing issues and tries to fix them
  itself.
* Bad, because it is not open source, and the free plan is limited to 100 container tests per month.

### Trivy

* Good, because it is free and open source.
* Good, because it also detects configuration issues, such as the handling of secrets.

### Grype

* Good, because it is free and open source, and checks the most popular CVE databases using an SBOM generated by Syft.

### CoGuard

* Good, because it scans configuration files inside the container for security and best practice violations.
* Bad, because it is not open source, and the free plan has limited features.

## More Information

The original decision of 2024-01-22 used Trivy to scan the Docker image in every pull request and Snyk to scan the
Docker image on a schedule. The Snyk Docker image scan was removed because its results were not used, and the Trivy
scan in every pull request was replaced by the nightly scan
([#4830](https://github.com/infonl/dimpact-zaakafhandelcomponent/pull/4830)).
