# Use Trivy and Snyk for Docker image scanning

## Context and Problem Statement

ZAC must be a secure component. The ZAC Docker image may contain security vulnerabilities. Which tools do we use to
scan it?

## Decision Drivers

* Detect vulnerabilities before they reach production
* Free to use
* Different scanners find different issues, so a mix of tools gives better coverage

## Considered Options

* Snyk
* Trivy
* Grype
* CoGuard

## Decision Outcome

Chosen option: "Trivy and Snyk": Trivy scans the ZAC Docker image for every pull request, and Snyk (free community
account) scans the Docker image on a regular schedule.

### Consequences

* Good, because issues are found per pull request, before they reach production, and by regular scans.
* Bad, because the two scanning tools overlap.

### Confirmation

The workflows `.github/workflows/trivy-docker-image-scan.yml` and `.github/workflows/snyk-code-scan.yml`.

## Pros and Cons of the Options

### Snyk

* Good, because it takes a developer-first approach: it guides developers in fixing issues and tries to fix them
  itself.
* Bad, because it is not open source, and the free plan is limited to 100 container tests per month.

### Trivy

* Good, because it is free and open source.
* Good, because it also detects configuration issues, such as the handling of secrets.

### Grype

* Good, because it is free and open source, and checks the most popular CVE databases using an SBOM generated by Syft.

### CoGuard

* Good, because it scans configuration files inside the container for security and best practice violations.
* Bad, because it is not open source, and the free plan has limited features.

## More Information

CoGuard can be reconsidered in the future for scanning configuration files inside the container.
