# Release v5.0.1

**Released:** 2026-06-04

## What's Changed

## New features and improvements

- **PR #6088**: Pinned Open-forms Docker image updates in Renovate to versions below 3.5.0 to ensure compatibility with the next Dimpact PodiumD release.
- **PR #6110**: Fixed and stabilized end-to-end tests.
- **PR #6069**: Replaced the provider-based BRP protocollering model (iConnect/2Secure) with a fully header-driven approach where every protocollering header name is individually configurable via environment variables. Introduces `BrpProtocolleringContext` for thread-safe header propagation and adds configurable BRP request/response logging via `BRP_LOG_LEVEL`.
- **PR #6068**: Address information for bedrijven in the zaak UI is now fully formatted and includes the address type label (bezoekadres/correspondentieadres). Address formatting now derives the display string from individual fields rather than relying on the inconsistently formatted `volledigAdres` from the KVK API.

## Bug fixes

- **PR #6060**: Aligned `doorlooptijd_behandeling` for Test zaaktype 1 and 3 in the local dev seed with TEST/PROD values (`P1Y`), so that per-form task fatal dates are correctly distinct when running locally instead of all collapsing to the zaak's fatal date.
- **PR #6073**: Fixed mail template creation failing due to JSON deserialization error. The ngx-editor auto-detects output format from the first `writeValue` call; when creating a new template the initial empty value was converted to null, causing the editor to output ProseMirror JSON objects instead of HTML strings.
- **PR #6074**: Fixed a bug where disabled form fields (e.g. `ontvangstdatum` setting status to `definitief`) had their values ignored when saving or editing a document. The form now uses `getRawValue()` to include values from disabled fields.
- **PR #6072**: Fixed the initiator block on the zaak detail page — the "Aanvraagspecifieke contactgegevens" header is no longer shown when contact details are empty, and bedrijfsgegevens now shows the same info-icon hint for aanvraagspecifiek phone/email as persoonsgegevens.
- **PR #6093**: Fixed the `reden` field not being required when releasing taken or zaken, and refactored `taken-vrijgeven-dialog.component.ts` to use ZAC components with TanStack mutations, aligning it with the `zaken-vrijgeven-component` approach.
- **PR #6094**: Fixed BPMN task assignment to store group and user IDs instead of full names/descriptions, so task forms correctly resolve assignees by ID.
- **PR #6065**: Fixed the Form.io post-submit confirmation text flashing below the submit button before navigation completes in BPMN task forms by suppressing it via CSS in the shadow DOM.
- **PR #6107**: Fixed BPMN task forms showing employee and group IDs as display names instead of full names, following up on the ID-based storage change.
- **PR #6108**: Fixed the "Besluit Vastleggen" button being incorrectly visible during the intake phase when a zaak had the status "Wacht op aanvullende informatie". This status type is now included in the intake phase check.
- **PR #6109**: Fixed stale business profile data being shown in the zaak view after linking a new bedrijf as initiator. Profile fields are now cleared and refetched when the initiator changes.
- **PR #6111**: Fixed betrokkenheid matching for klanten in zaken. The betrokkenheid prefix (introduced in PZ-10300) is now also applied when matching the `Betrokkenheid` field.
- **PR #6117**: Fixed an issue where a locked document that was unlinked from a zaak could not be unlocked from the document detail view.
- **PR #6119**: Fixed Helm chart configuration to correctly render the `BRP_API_KEY` value from `brpApi.apiKey` and set a default value for `BRP_API_KEY_HEADER`.
- **PR #6124**: Restored the `--helm-extra-args` flag in the Helm chart testing install step so that test values are correctly layered on top of each install run.
- **PR #6120**: Fixed several issues in the zaak create and postpone dialogs: BAG object field no longer appears grayed out, BAG objects are correctly stored on creation, and the postpone dialog "reason" input field now has the correct Dutch translation.
